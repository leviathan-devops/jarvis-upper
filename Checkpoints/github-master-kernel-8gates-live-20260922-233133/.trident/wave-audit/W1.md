## §2 WHY — does the reason hold against the spec?

The wave existed to install the GATE-HEADER STANDARD: every gate names (a) its Jev count and
(b) the ARTIFACT CLASS it applies to. The DPL1 spec §9 names the anti-pattern this closes, and
the spec §5 states the core insight: *"a gate is a (predicate x artifact-class) pair."*

**Three misfires this session were that class:**
- W-1 fired on EVERY `src/` commit — derived from a repo WITH `extensions/`; this repo has none
- W-9 fired on a GitHub PR template — derived for engineering docs
- W-9 fired on a checkpoint manifest + its byte-identical copies — a snapshot, not a doc

`header_ok` now returns exit 1 on any gate missing its ARTIFACT CLASS line, so the defect is
visible IN THE SOURCE rather than discovered by a firing.
