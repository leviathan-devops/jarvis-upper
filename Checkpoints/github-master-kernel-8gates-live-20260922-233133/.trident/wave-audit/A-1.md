## §4 THE DEFECT I FOUND — and the steer that fixed it

**The defect, measured by me:** the desk's edit to `src/guardrail.ts` REPLACED the line
`import { Database } from "bun:sqlite";` with the contract import, while `Database` remained in
the function signature.

```
$ bunx tsc --noEmit
src/guardrail.ts(12,31): error TS2304: Cannot find name 'Database'.
```

**Why the unit test did not catch it:** `bun test tests/guardrail_stale.test.ts` -> **5 pass /
0 fail**. The test suite does not type-check. A broken import is invisible to a passing
assertion. This is exactly why A-1's done-when names `bunx tsc --noEmit` as a SEPARATE
criterion from the test — and why the audit re-runs both.

**The steer:** I sent desk-a1 the exact finding plus the one-line fix (keep BOTH imports).

**The fix verified:** `src/guardrail.ts:3` now reads `import { Database } from "bun:sqlite";`
and `src/guardrail.ts:4` carries the contract import. Both are present.
