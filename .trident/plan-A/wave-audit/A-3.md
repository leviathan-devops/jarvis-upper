The desk asked permission (correctly) and I authorized with a constraint. The result:

```ts
src/guardrail.ts:39-43
// INVERSION: the factory ORDERS (merge_ordered), the human merges. Within one
// ... merge_ordered before its dependent is evaluated. Requiring "merged" here
// would deadlock every multi-PR plan. Token spelling kept (DEP-UNMERGED).
if (!st || (st.state !== "merged" && st.state !== "merge_ordered")) reasons.push(`DEP-UNMERGED:${d.f}`);
```

**The desk honoured the constraint exactly:** the state predicate widened, the token spelling
`DEP-UNMERGED` kept. No stale token asserted by a test that no longer exercises it.

**Why this mattered:** without it, the inversion would DEADLOCK. The factory no longer sets
`merged`, so every intra-plan dependency would read as unsatisfied and `executePlan` would halt
on the first multi-PR plan. This is a real correctness bug, found by the desk reasoning about
the inversion rather than pattern-matching the old code.
